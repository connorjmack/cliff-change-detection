# Repository Guidelines

## Project Structure & Module Organization
- `code/pipeline/`: numbered pipeline scripts (0-9) run sequentially.
- `code/streamlit/`: Streamlit survey browser and its README/requirements.
- `code/training/`: model training scripts (e.g., beach removal RF).
- `code/figure_making/`: analysis/visualization scripts.
- `utilities/`: models, parameters, shapefiles, and reports used by the pipeline.
- `survey_lists/`: survey inventory CSVs generated by steps 0/1.
- `results/`: outputs per location (cropped, nobeach, noveg, m3c2, erosion, deposition).

## Build, Test, and Development Commands
- `conda env create -f environment.yml` and `conda activate cliff-change-detection`: recommended environment setup.
- `python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`: pip setup alternative.
- `python3 code/pipeline/0_make_survey_lists.py --location SanElijo`: initial survey inventory.
- `python3 code/pipeline/1_update_survey_lists.py --all`: update inventories.
- `python3 code/pipeline/2_crop_files_parallel.py --location SanElijo --replace`: crop with PDAL.
- `python3 code/pipeline/5_remove_veg_parallel.py SanElijo --cc "/path/to/CloudCompare"`: vegetation removal.
- `xvfb-run --auto-servernum python3 code/pipeline/6_m3c2_parallel.py SanElijo`: headless M3C2.
- `streamlit run code/streamlit/survey_browser.py`: launch survey browser.

## Coding Style & Naming Conventions
- Python scripts use 4-space indentation and `snake_case` for variables/functions.
- Pipeline scripts are numbered to reflect execution order (e.g., `6_m3c2_parallel.py`).
- Outputs follow `results/<Location>/` and `survey_lists/surveys_<Location>.csv` naming patterns.
- No enforced formatter/linter; keep changes minimal and consistent with existing style.

## Testing Guidelines
- Minimal automated tests; `code/pipeline/test_step9_cleaning.py` exists for step 9.
- Many scripts accept `--test N` to process a small sample (see script help).
- Validate outputs via generated reports/plots in `code/pipeline/reports/` and `utilities/`.

## Commit & Pull Request Guidelines
- Commit history uses short, informal summaries (e.g., "Quick update"). Follow that tone.
- Include what changed and which pipeline step or location it affects.
- PRs should describe the data scope (location/date), steps run, and key outputs; attach relevant plots or report paths when available.

## Configuration & External Dependencies
- PDAL is required for cropping; CloudCompare is required for CANUPO/M3C2 steps.
- Path handling assumes `/Volumes/group/LiDAR` (macOS) or `/project/group/LiDAR` (Linux); update only if adding new locations or deployments.
